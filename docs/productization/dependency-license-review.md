# Dependency license closure review

This is an engineering/compliance inventory for AgentGuard 1.0.0rc1. It is
not legal certification or a legal opinion. No dependency was upgraded,
removed, replaced, repinned, or rebuilt for this review.

## Exact inputs and scope

The inventory is derived from the exact CycloneDX 1.5 SBOM generated by Docker
Scout v1.24.0 for the approved RC image:

`sha256:d67cdf9eab0bc00efe62f1535e0e954fa7b535fe69c87d0b075d12394c4acfd4`

The SBOM contains 122 components: 2 first-party AgentGuard packages, 54
third-party PyPI packages, 65 Debian/RPM package records, and 1 generic Python
runtime record. The 15 unique direct runtime dependency names declared by the
server and SDK metadata all map to SBOM components. The remaining 39 PyPI
components are transitive runtime packages; the 66 OS/runtime components are
reported separately because they are inherited from the distroless Debian 13
runtime and are not Python dependency edges.

The development lock contains `bandit`, `coverage`, `pip-audit`, `pytest`, and
`pytest-cov`. These are development-only and are not present in the exact RC
image; they are not counted as runtime SBOM components.

## Closure result

Primary classifications are mutually exclusive per component. A component
with multiple license IDs reported by the SBOM is classified as
`DUAL_OR_MULTI_LICENSE`, but the inventory preserves the IDs as observed and
does not pretend that they form a selected SPDX expression. This is important
for OS packages whose SBOM records identify licenses found in bundled source
or copyright material.

Six exact-version PyPI distributions were resolved from bundled dist-info
license files: `googleapis-common-protos`, `Jinja2`, `boto3`,
`python-dateutil`, `protobuf`, and `s3transfer`. `botocore` was not resolved
from the host because its installed version does not match the SBOM; `uvloop`
has no matching local dist-info record. The remaining unresolved rows are
listed by name in the machine-readable closure artifact and matrix.

The previous 118-item manual-review count is reduced to a 71-item evidence
and owner-review queue: 38 multi-ID records, 13 single strong-copyleft
records, 3 weak-copyleft records, and 17 distributed components without
usable license metadata. This is a reduction in the engineering inventory,
not a legal clearance.

## Copyleft re-evaluation

The previous 47 copyleft-related count is confirmed as 47 components with an
observed GPL/AGPL/LGPL/MPL-family identifier: 44 contain GPL/AGPL-family IDs
and 3 contain LGPL/MPL-family IDs only. There are no AGPL identifiers. Of the
44 strong-family components, 31 are also multi-ID OS records and therefore
appear under the primary `DUAL_OR_MULTI_LICENSE` classification; 13 are
single-ID strong-copyleft records. The count is not treated as an automatic
incompatibility finding.

The exact SBOM has 33 components carrying `GPL-2.0-only`, including OS/runtime
records. Their presence alongside Apache-2.0 AgentGuard source requires an
explicit compatibility review of the actual package boundary, linkage/import
behavior, modifications, and applicable notices. The inventory found no
vendored third-party source, patch overlay, or AgentGuard modification of
these components. It does not conclude whether any combined-work or source
obligation is triggered.

`psycopg` and `psycopg-binary` are the two exact PyPI LGPL-3.0-only records;
`certifi` is the exact PyPI MPL-2.0 record. Their unchanged package/import
facts and notice/source review requirements are recorded in the matrix.

## Unresolved distributed components

The 17 third-party components still classified as
`NO_LICENSE_METADATA` are:

`libcom_err`, `botocore`, `python3.13-venv`, `libxcrypt`, `python`, `libzstd`,
`media-types`, `tzdata-legacy`, `libcrypt1`, `tzdata`, `gcc-14`, `krb5-libs`,
`libselinux`, `keyutils-libs`, `pcre`, `cyrus-sasl-lib`, and `uvloop`.

For each row, the review attempted exact SBOM metadata first, then exact local
installed package metadata where applicable. No matching Debian/distroless
copyright database was mounted in the repository environment. No license is
inferred from a package name, parent project, or unrelated host version.

## Notices, license texts, and source obligations

`THIRD_PARTY_NOTICES.md` is a candidate, version-specific inventory, not a
release-ready notice bundle. It intentionally does not reproduce full
licenses or invent copyright owners. Before a public distribution, the owner
must validate the authoritative text and package-specific notices, preserve
the repository `LICENSE`, and add required texts under
`licenses/third-party/<component>-<version>.txt` or an equivalent package
metadata bundle.

The current source-distribution status is `BLOCKED`: 44 components have
strong-family IDs, 3 have weak-family IDs, and the exact obligations for the
multi-ID OS records and the 17 no-metadata records have not been resolved.
Potential written-offer, corresponding-source, relinking, install-information,
or network-use questions are deliberately left for owner/legal review rather
than asserted as conclusions.
