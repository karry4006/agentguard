# AgentGuard V9.1 Runtime Remediation Experiment

Status: **SUPERSEDED — V9.2 DISTROLESS PROMOTED**

This was a bounded experiment against the known-good V9 image. Its candidate
results were later completed by the V9.2 compatibility decision; no risk
exception or VEX suppression was created.

## Compatibility baseline

At the time of this experiment AgentGuard remained on Python 3.12. V9.2 later
validated the server on Python 3.13 and retained the SDK boundary at `>=3.12`.

Official Distroless currently publishes `gcr.io/distroless/python3-debian13`
with Python 3.13 and no shell. Official Chainguard publishes a minimal
`cgr.dev/chainguard/python` runtime; the public `latest` candidate evaluated
here is Python 3.14.7. The official Chainguard directory lists versioned 3.12
tags, but the tested public pull of `cgr.dev/chainguard/python:3.12` returned
not found/access unavailable, so it is not an available baseline dependency.

Sources: [Distroless image list and support policy](https://github.com/GoogleContainerTools/distroless/blob/main/README.md),
[Distroless Python documentation](https://github.com/GoogleContainerTools/distroless/blob/main/python3/README.md),
[Chainguard Python versions](https://images.chainguard.dev/directory/image/python/versions),
[Chainguard Python overview](https://images.chainguard.dev/directory/image/python/overview).

Both candidates had no Critical/High Scout vulnerabilities, no fixable

`FIXABLE=0`, `UNTRIAGED=0`.

## Proof runtime checks

- Both proof images were built with a builder/runtime split.
- Build tools, pip, package caches, and compiler material were not copied to
  the final runtime stage.
- Both started as UID 65532 with read-only rootfs, `cap_drop=ALL`,
  `no-new-privileges`, and a bounded noexec `/tmp`.
- Both returned FastAPI `/health/live` HTTP 200 and imported AgentGuard.
- Distroless and Chainguard runtime images have no shell; the proof CMD uses
  vector form and does not depend on `/bin/sh`.
- No full V0–V8 suite was run against either candidate because both require a
  separate Python minor-version compatibility decision (3.13 or 3.14) and
  neither can replace the declared Python 3.12 baseline automatically.

## Decision

V9.2 selected Distroless after the required compatibility gate: clean Python
3.13 installation and full live regression passed, PostgreSQL/migrations,
backup/restore, restart, least privilege, and security scans passed. The
selected base remains the pinned Distroless digest shown above. Chainguard was
not selected because the usable tested tag was Python 3.14 and the exact 3.12
pull was unavailable. The prior Python 3.12 image and V9 triage remain the
rollback/historical record.
